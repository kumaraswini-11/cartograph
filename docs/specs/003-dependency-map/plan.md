# 003 — Dependency map: plan

**Spec:** [spec.md](spec.md)
**Status:** Approved

## Approach

The map's arithmetic is a new package, `packages/graph` (`@workspace/graph`):
folding, labels, box sizes, neighbours, role counts and the layout, all pure
functions over files and edges (`docs/project-doc.md`: graph calculations
are pure functions). The interface lives in the app, in
`apps/web/src/components/map/`, drawn with
[React Flow](https://reactflow.dev) and laid out with
[dagre](https://github.com/dagrejs/dagre), as ADR 0001 chose.

Until `008` stores analyses, the map shows one fixed sample: the parser's
and detection's results for `shadcn-ui/taxonomy` at its golden commit
(`002`), generated by a script and committed. A server function reads it and
returns only what the map needs; the route renders the shell on the server
and draws the map in the browser.

## Data

```ts
type MapInput = {
  repository: string // "owner/name"
  commit: string
  files: Array<{
    path: string
    folder: string
    lines: number
    fanIn: number
    fanOut: number
    role: string
    entryPoint: boolean
  }>
  edges: Array<{ from: string; to: string; typeOnly: boolean }>
  taxonomy: Array<{ role: string; tier: Tier; files: number }>
  coverage: number | null // 001 FR-020
}

type Box = {
  id: string // the folder's path; "" for the root
  label: string // the shortest unique form (FR-006)
  folders: Array<string> // itself and every folder folded into it
  files: Array<string>
  fanIn: number // distinct boxes with an edge in
  fanOut: number
}
```

## Decisions

- **D-01** A graph package of its own. _Why:_ the project doc keeps graph
  arithmetic pure and apart from the interface, and `004`, `005` and `010`
  reuse it (blast radius, insights, the chat's lookups) on the server and in
  the browser. It imports no React, no React Flow and no storage.
- **D-02** React Flow `12.12.0` (`@xyflow/react`) and dagre `3.1.1`
  (`@dagrejs/dagre`), pinned in the catalog. _Why:_ ADR 0001's choice,
  checked on 2026-10-16. React Flow ships keyboard focus and selection for
  nodes and edges
  ([accessibility](https://reactflow.dev/learn/advanced-use/accessibility)).
  React Flow recommends dagre for tree-like layouts, and it's fast and
  synchronous
  ([layouting](https://reactflow.dev/learn/layouting/layouting)).
  `@dagrejs/dagre` is the maintained line; the original `dagre` package was
  last released in 2019. _Rejected:_ elkjs (about 1.4 MB, asynchronous, and
  React Flow seldom recommends it).
- **D-03** The map is drawn in the browser, in `<ClientOnly>`, with a
  fallback that fills the map's column at its final size (FR-022, C-06).
  The rail, the banner and the pane render on the server. _Why:_ AGENTS.md
  puts browser-only UI in `<ClientOnly>`; React Flow can render on the server,
  but only with measured nodes and handles, which its docs call an advanced
  case ([SSR](https://reactflow.dev/learn/advanced-use/ssr-ssg-configuration)),
  and the map needs the browser for every interaction anyway.
- **D-04** Box sizes are computed, never measured. Labels are paths set in
  monospace (FR-019), so a label's width is its length times one character's
  width; height grows by a step each time its dependents double, so a box
  with more dependents is always taller (AC-12) and no hub dwarfs the map. _Why:_ the layout then
  comes from data alone, the same everywhere (FR-012), and is known before
  anything is drawn.
- **D-05** Opening or closing a panel lays the map out again with the
  panel's size, then refits only outward (FR-011, C-03). _Why:_ a panel in
  place of its box would overlap its neighbours; the layout of a given set of
  open panels is still the same every time. Layout is dagre, left to right:
  a file's dependencies sit to its right.
- **D-06** The sample is the golden checkout of `shadcn-ui/taxonomy` (`002`),
  generated by `pnpm --filter web sample` and committed. _Why:_ the user's
  choice; 131 files in 35 folders exercise folding (more than `FOLD_TARGET`),
  and the map input is about 55 KB. The script is the network's only user.
- **D-07** The script derives the map input once, when it writes the sample,
  and the app reads only that. _Why:_ deriving per request would put the
  parser, and oxc's native binary, into the deployed server to read a fixed
  file; the map still reads both results unchanged (C-02), and `tsc` checks
  the sample's shape on every build. The parser's result for the sample is
  125 KB, mostly imports the map doesn't draw.
- **D-08** Keyboard access (FR-023): every box, panel header and row is a
  shadcn `Button` or an `Item` rendered as a button, so Enter and Space
  work and the focus ring shows; React Flow's own node focus is off
  (`nodesFocusable={false}`, `disableKeyboardA11y`), as its docs advise for
  interactive content, so each box is one tab stop, in the picture's order.
  A box and its panel are different nodes, so when one replaces the other the
  new one takes the focus. The rail is an always-open `Sidebar` menu:
  shadcn keeps `ToggleGroup` for 2 to 7 options, and a taxonomy can hold 18.
  Behaviour follows Base UI's docs; shadcn supplies the components.
- **D-09** Light and dark only (FR-021), as the theme already works: the
  first visit follows the system, and a choice survives a reload with no
  flash. React Flow's own colours follow the same tokens.
- **D-10** One source for each concern. Paths are compared, split into
  folders and named by `@workspace/parser/paths` (pure, so the browser can
  use it), and the commands' `<directory> [--out <file>]` by
  `@workspace/parser/cli`; the graph package declares `sideEffects: false`,
  so a page that imports one value from it doesn't also load dagre.
- **D-11** Not-found, error and pending pages, asked for by the user while
  the shell was built: the router's `defaultNotFoundComponent`,
  `defaultErrorComponent` and `defaultPendingComponent` (TanStack Router's
  not-found and errors guide), set once in `src/router.tsx`. The not-found
  page answers with status 404; the error page offers trying again
  (`router.invalidate()`) and shows the technical message in development
  only. They and the empty panes share `EmptyState`, a thin composition of
  shadcn's `Empty` in `packages/ui/src/components`, since it appears more
  than three times (AGENTS.md: the rule of three).
- **D-12** Search and link previews, asked for by the user: every page sends
  Open Graph's four required tags (`og:title`, `og:type`, `og:image`,
  `og:url`, [ogp.me](https://ogp.me/)), a description, a canonical link,
  and X's `summary_large_image` card, the one tag X can't read from Open
  Graph; the home page adds `WebSite` structured data for Google's site
  name ([site names](https://developers.google.com/search/docs/appearance/site-names)).
  One helper, `seo()` in `src/lib/site.ts`, builds them from one site
  config; TanStack Router keeps the deepest route's copy of each tag.
  Addresses are absolute, from `VERCEL_PROJECT_PRODUCTION_URL`, which Vercel
  sets on every build, previews included, and which `turbo.json` declares
  so Strict Mode passes it to the build. A build for Vercel without it
  stops rather than publish links to localhost; Vercel is detected as Nitro
  detects it (`std-env`). The 1200 × 630 share image is drawn
  by `scripts/og-image.ts` and committed. Titles put the page first and
  the site's name after it, the home page the brand line (Google: title
  links). `twitter:url` isn't one of X's card tags; it carries the page's
  address anyway, since link checkers ask for it. The home description stays
  within three lines on mobile (at most 120 characters).

## Stack notes

- React Flow renders a node only when it has a size; the layout supplies
  every node's width and height, so nothing waits on measuring.
- React Flow's `fitView` with `maxZoom` set to the current zoom fits only
  outward (FR-011); its duration is 0 when the system asks for reduced
  motion (FR-020).
- dagre misreads an empty node id, and the root box's id is `""`, so every
  id enters dagre prefixed (`box:`); found when the sample's root box crashed
  the first layout.
- shadcn's `Sidebar` always imports its mobile `Sheet` and `Tooltip`, even
  when it never collapses: the page's own JavaScript is 36.7 KB gzipped, and
  React Flow with dagre (77.7 KB) loads with the map, after the shell.
- TanStack Router reloads loader data when it's stale, by default at once;
  the sample is fixed, so its route sets `staleTime: Infinity`.

## Testing

- Vitest on `@workspace/graph` with small fixtures: folding and its
  threshold (AC-01, AC-02, and a repository of one folder), edges ending on
  boxes or rows that exist (AC-03), the same layout twice (AC-04), sizes
  (AC-12), labels (AC-13), selection and role counts.
- The coverage banner below `COVERAGE_PARTIAL_BELOW` (AC-10) is checked by
  rendering it with `react-dom/server` in a test, open and collapsed, since
  the sample's figure (97.5%) is above the threshold; in the browser, the
  sample shows no banner.
- Before review, in headless Edge driven over the DevTools protocol: no
  console errors; opening, selecting and choosing a role make no request
  (AC-07); Tab reaches every box and Enter opens it, moving the focus to its
  panel (AC-18); every row and header fits; light and dark.
- In a browser, on the preview deployment: AC-05 to AC-11 and AC-14 to
  AC-18, each as its row says.

## Risks

- A repository much larger than the sample makes the first layout slow →
  folding caps the map at `FOLD_TARGET` boxes before dagre runs; files are
  laid out only inside open panels.
- React Flow's default styles fight the theme → it's styled from the
  repository's tokens, with only its base stylesheet imported.
